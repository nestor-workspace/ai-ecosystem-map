# How the site is built

`dist/index.html` is generated by one Node script. There is no framework, no bundler,
no template engine and no CSS pipeline — `scripts/build.mjs` reads a JSON file and
writes an HTML string built from a template literal.

The whole toolchain is:

| Piece | What it is |
| --- | --- |
| Runtime | Node ≥ 22 (`"type": "module"`, plain ESM). CI runs Node 22. |
| Templating | A JavaScript template literal in `scripts/build.mjs`. |
| Diagram | Inline SVG, coordinates written by hand in `data/architecture.json`. |
| Styling | One inline `<style>` block, CSS custom properties, `prefers-color-scheme`. |
| Interaction | ~60 lines of inline vanilla JS, no library. |
| Tests | `node --test` (`tests/architecture.test.mjs`), no test framework. |
| Dependencies | `simple-icons` (runtime), `@lobehub/icons-static-svg` (dev). Nothing else. |

Everything else is the Node standard library (`node:fs/promises`, `node:test`).

The output is a **single self-contained document** (~600 KB): the CSS, the script, the
SVG and every brand PNG (base64 data URIs) live inside it. It makes zero network
requests, so it works opened straight from `file://` and GitHub Pages only has to serve
one file.

## Pipeline

```
data/architecture.json
   │
   ├─ scripts/validate.mjs   structure: ids, zones, statuses, geometry
   │
   ├─ scripts/build.mjs      render + text-fit checks → dist/index.html
   │
   └─ tests/architecture.test.mjs   asserts on the data *and* on the generated HTML
```

`npm run verify` runs the three in order and is exactly what CI (`.github/workflows/ci.yml`)
and the Pages deploy (`.github/workflows/pages.yml`) run. Nothing else gates the site.

Two things follow from that:

- **`dist/index.html` is committed** and a fresh build must be byte-identical to it.
  Rebuild and commit the output in the same change, or the repo lies about what is published.
- **The build is the linter.** `validate.mjs` and `build.mjs` both `process.exit(1)` on a
  list of collected errors instead of throwing on the first one, so you get every problem
  in one run.

`npm run dev` is `npm run build` followed by `python3 -m http.server -d dist 8000`. It is a
one-shot generator — there is no watcher, so re-run it after every edit.

## Layout is manual, on purpose

There is no auto-layout engine (no dagre, no elk, no force simulation). Every `x`, `y`,
`width` and `height` in `data/architecture.json` is an absolute SVG user unit inside
`viewBox="0 0 meta.width meta.height"`. Zones are drawn first, then edges, then nodes on top.

The trade: adding a node means moving its neighbours by hand. In exchange the layout is
stable (a data edit never reshuffles the whole picture) and diffs stay readable.

Hand placement is only safe because the checks are strict. `validate.mjs` rejects:

- a node whose box escapes its zone — the first 66 px of a zone (`ZONE_HEADER_HEIGHT`) are
  reserved for the zone title and subtitle, so nodes must start below that;
- any two node boxes that overlap (naive O(n²) pair scan, fine at 34 nodes);
- duplicate ids, unknown zone references, dangling or self edges, unknown `status` /
  edge `kind` values.

## Text fitting without a browser

The build has no layout engine to ask how wide a string renders, so it estimates:

```js
const SUBTITLE_CHAR_PX = 6.4;  // measured worst case ≈ 6.31 at 11px
const LABEL_CHAR_PX = 9.8;     // measured worst case ≈ 9.76 at 15px semibold
```

Both are rounded **up** from the widest ratio observed at render time. The estimate is
deliberately pessimistic: refusing a box that would just barely fit is cheaper than shipping
truncated text. If the font stack changes, re-measure the bounding boxes rather than nudging
these constants blindly.

The usable text width is the box width minus a fixed gutter (86 px, or 84 px for a `compact`
node) covering the left padding, the logo disc and the gap after it. The build **fails** —
it does not truncate — when:

- a label is wider than the space left of the box;
- a prose subtitle would need more than two lines;
- a list subtitle has an item too wide for one line;
- the stacked lines are taller than `node.height`.

The height check duplicates `renderNode`'s geometry (label baseline at +31 px, or +23 px
compact; first subtitle 22 px below it; 15 px per extra line; `DESCENDER = 4`). **Those
numbers must stay in sync** — change one side and the check silently stops matching what is
drawn.

## Icons: three tiers, no silent fallback

`renderSvgMark` resolves a node's mark in this order:

1. **`iconAsset`** — a local PNG in `assets/`, read at build time, base64-encoded into an SVG
   `<symbol>` and referenced with `<use>`. Used for marks that are not in any icon set
   (Hermes Agent, Docmost, rabbit, OpenClaw, MyPacer) and for the personal Hermes avatar.
   The square image is clipped to a circle by a single `clipPath` with
   `clipPathUnits="objectBoundingBox"`, so one clip path serves every disc size.
2. **`icon` / `icons`** — brand slugs. LobeHub is tried first (its SVG is unwrapped: outer
   `<svg>` tag and `<title>` stripped, inner markup kept), then Simple Icons (a single `path`
   plus the brand `hex`). Up to three marks fit in one disc; they shrink from 58 % to 38 % of
   the disc when there is more than one.
3. **`iconText` / initials** — a coloured disc with letters.

Tier 3 is the trap: an unresolved slug would fall through to initials and look intentional.
`checkIconResolves` therefore fails the build on an unknown `iconAsset` or unresolved slug
**unless** the node also sets `iconText`, which makes the fallback an explicit choice.

Brand PNGs should be stored at roughly the size they render (96 px is plenty for a 42 px
disc) — they are inlined, so every extra pixel ships to every visitor.

## Edges: geometry, not routing

There is no router and no obstacle avoidance.

- `defaultSides` picks the anchor sides from the centre-to-centre delta. The comparison is
  `|dy| > |dx| × 0.72`, biased toward vertical: the map reads as stacked layers, so a link
  only leaves sideways when it is clearly more horizontal than vertical. `fromSide` /
  `toSide` in the data override this per edge.
- `bezierPath` emits one cubic Bézier whose control points are pushed straight out of each
  anchor by `max(45, 0.46 × span)`, which is what gives the curves their consistent flare.
- Edge labels sit at the curve's analytic midpoint — `cubicMidpoint` evaluates the Bézier at
  `t = 0.5` as `(P₀ + 3·P₁ + 3·P₂ + P₃) / 8` — nudged 7 px up, with a thick surface-coloured
  stroke under the fill (`paint-order: stroke`) so the text punches a hole in the line it
  crosses.
- One `<marker>` arrowhead is generated per edge kind so each keeps its own colour.

## Interaction and theming

Selection is class toggling; the CSS does the rest. Clicking a node collects the ids at both
ends of every incident edge, then marks each SVG node group, catalogue card and edge as
`is-selected`, `is-related` or `is-dimmed`, and puts `selection-active` on `<body>` so the
dimming rules only apply while something is selected.

Raising the group's opacity is not enough on its own: the `<path>` carries its own, so a
related edge would stay at the 54 % it uses at rest. The selection rule therefore lifts the
path to full opacity and thickens it. The thickening is expressed as `calc(var(--w) + 1)` —
each edge kind declares its resting width in `--w` on the group, so the emphasis is a delta
that keeps the hierarchy (the primary flow stays the heaviest line) instead of flattening
every kind to one width. Arrowheads use `markerUnits="strokeWidth"`, so they grow with it.

Graph nodes and catalogue cards share the same `data-node-id`, which is why clicking either
one highlights both. Both are `role="button" tabindex="0"` and answer Enter/Space; Escape and
a click on the diagram background clear the selection. On load, a `#node-id` fragment
pre-selects that node, so any component is deep-linkable.

Theming is pure CSS — a light palette in `:root`, a dark override under
`@media (prefers-color-scheme: dark)`. No JS is involved and there is no theme toggle.

Both legends are derived from what the data actually contains — a node status nobody carries
and an edge kind nobody draws produce no legend entry. Adding a vocabulary value therefore
means adding its label to `STATUS_LABELS` or `EDGE_LABELS` and its CSS rule; forgetting the
label is what makes an entry silently disappear.

## Data reference

### `meta`

`title`, `subtitle`, `updated` (ISO date, shown in the header), `width` / `height` (the SVG
`viewBox`; must contain every zone).

### `zones`

| Field | Notes |
| --- | --- |
| `id` | Referenced by `node.zone`. |
| `title` | Leading `"N. "` is split off into the catalogue's numbered badge. |
| `subtitle` | One line, under the title. |
| `kind` | `input` · `process` · `storage` · `external` · `neutral` — picks the fill colour. |
| `x` `y` `width` `height` | Absolute SVG units. |

### `nodes`

| Field | Notes |
| --- | --- |
| `id` | Stable; edges and `#hash` deep links reference it. |
| `zone` | Must exist; the box must fit inside it, below the 66 px header. |
| `label` | Width-checked against the box. |
| `subtitle` | String (prose, wrapped, max 2 lines) **or** array of strings (enumeration, one item per line, never reflowed). Prefer the array when listing distinct products or layers. |
| `x` `y` `width` `height` | Absolute SVG units; checked for zone containment and overlap. |
| `status` | `active` · `experimental` · `planned` — the corner dot. |
| `icon` / `icons` | Brand slug(s), LobeHub then Simple Icons, max 3 rendered. |
| `iconAsset` | Key into the local PNG map in `build.mjs`, wins over slugs. |
| `iconText` | Explicit initials; also the opt-in that lets an unresolved slug pass the build. |
| `iconColor` | Disc colour behind those initials. |
| `compact` | Smaller mark (32 px) and tighter baselines, for short boxes. |
| `emphasis` | Draws the box with the primary-colour stroke. |

### `edges`

| Field | Notes |
| --- | --- |
| `from` `to` | Node ids; both must exist and differ. |
| `kind` | `primary` · `active` · `ondemand` · `planned` · `experimental` — colour, dash pattern and arrowhead. |
| `label` | Optional, drawn at the curve midpoint. Keep it short, nothing clips it. |
| `fromSide` `toSide` | `top` · `bottom` · `left` · `right`, override the automatic anchor choice. |

## Adding a node

1. Add the node to `data/architecture.json` with an id, a zone and a box that fits without
   overlapping — widen the zone (and `meta.height`) if there is no room.
2. Give it an icon: a slug if the brand is in Simple Icons or LobeHub, otherwise a PNG in
   `assets/` plus an entry in `brandAssetFiles` in `scripts/build.mjs`. Set `iconText` if you
   deliberately want initials.
3. Add its edges.
4. `npm run verify`, then commit the regenerated `dist/index.html` alongside the data change.
